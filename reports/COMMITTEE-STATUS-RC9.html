What changed

Server-side entitlements, not cosmetic pricing buttons

Trial expiry and subscription state now gate vendor creation/screening, opportunity sync/enrichment, provider-backed market context and workspace mutations. Existing history remains readable. The scheduler skips inactive tenants before upstream provider work.

Stripe boundary

Hosted Checkout + Portal + signed webhooks

RC9 implements Stripe through a narrow zero-dependency REST adapter. Webhooks are verified from the raw body with HMAC-SHA256 and a bounded timestamp window; processed event IDs provide idempotency. Production readiness rejects mock billing.

QA finding

A paywall bypass was found before release

The first RC9 draft blocked Vendor Watch but still allowed some secondary upstream opportunity actions after entitlement expiry. The server boundary was tightened before release. This is recorded rather than hidden.

Release process

Second full gate passed

The first full gate failed because the lifecycle smoke still modeled RC8 and did not include the newly required Stripe production settings. The harness was fixed and the entire gate rerun from zero: 79 tests, eight smoke flows, secret scan and clean diff.
